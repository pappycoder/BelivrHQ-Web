## Rollback

For code rollback, retain both cookie families, original helper aliases, existing asset URLs and physical vaults; do not delete pending work or reverse issued references. Roll back API and workers together to their preceding revision if necessary. The forward database migration is backward compatible; leave it applied when rolling back code.

For Docker ownership rollback, stop/remove only the new stack containers using `npm run docker:down` (never add volume deletion flags). Start the original Compose configuration from the previous committed revision with its original project name, container names, credentials and the same two existing physical volumes. Never run old/new PostgreSQL instances against one volume simultaneously. Verify healthy services and mounts before resuming writers. Restore a backup only for actual data damage, with writers stopped and explicit restore approval; a name rollback needs no data restore.

Keep old local paths and compatibility aliases until existing clients, vaults, printed labels, provider retries and pending payments have been accounted for.

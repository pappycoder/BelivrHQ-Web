# Shared date and time picker

The shared picker uses a calendar and a dedicated time panel instead of scroll wheels. Forms use the spacious dialog; filters and date selectors use a compact anchored popover (`picker="popover"`) without a page overlay. It has a tinted selection summary, month dropdown, directly editable year, previous/next month navigation, Today/Now shortcuts and consistent Clear/Cancel/Apply actions. Date/time panels sit side by side on desktop and stack on phones. Short screens scroll with a sticky action row. Theme tokens provide light and dark styling; reduced-motion preferences disable transitions.

Use `<Input picker="calendar" type="date" />` (also `time` and `datetime-local`). Existing `picker="wheel"` opt-ins and component exports remain compatible and render the new interface. The shared Input now defaults to this picker for date, time and local date-time fields, including filters, reporting ranges, notification filters and meeting-date selectors. Explicit `picker="native"` remains available for exceptional browser-native controls. Check-in uses the same dialog/panel with scheduled-date validation, previous/next occurrence controls and a Jump to today shortcut that targets the nearest valid occurrence. A valid date commits immediately and closes the popover.

Implementation lives in `src/components/ui/form-date-time-picker.tsx`; the former wheel component re-exports it for compatibility. Calendar-day tooltips are disabled in this picker while other Calendar consumers retain their defaults. Native fields, refs, names, keyboard entry, required/min/max/step constraints and React Hook Form bindings are preserved. Values retain native ISO/local strings without UTC conversion. Calendar helpers preserve years 1–99 and time components when selecting a new date.

Click a field or press Enter, Space or Alt+Down to open. Calendar days support the calendar keyboard navigation; time dropdowns use labelled Hour/Minute controls and optional Seconds when the native field requires them. Form dialogs commit through Apply; compact date popovers commit when a valid day or Today is selected. Both use the original input/change contract. Escape and outside dismissal preserve the value; form dialogs also offer Cancel. Optional fields offer Clear. Compact date popovers omit the large summary and redundant confirmation controls. Range filters retain their outer Apply dates/Clear dates controls, so selecting a calendar date changes the filter draft until that outer action is used. Focus returns to the original input, including inside another dialog.

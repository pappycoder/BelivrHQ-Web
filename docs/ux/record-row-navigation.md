# Clickable record rows

Rows reuse an existing read/open control or an identifying record link. `RowActions` marks its first available Open/View/Inspect/Review action. The shared document enhancer covers Paper `ListTable` grids, native `Table` rows and explicitly marked `data-record-row` lists, including services. Legal/rich-text HTML tables outside the shared record renderers are excluded. A row uses the same permission-gated control already displayed; it does not invent destination URLs or add read permissions.

Click blank space or text in an enabled row, or focus the row and press Enter, to open the existing destination. Ctrl/Cmd/Shift-click and middle-click on rows with link destinations open a new tab. Links, buttons, checkboxes, labels, selects, date inputs and editable controls keep their own behavior. Selected text does not activate the row. Rows with existing `onClick` handlers retain those handlers without delegated duplicate activation. Rows without a readable detail target remain informational; permission matrices, import errors and summaries do not acquire fabricated detail links.

The audit includes member/visitor/household registers, pending registration review, team/locations/role directories, services, events/registrations, departments/cell groups and rosters, forms, sermons/media and asset tables. Most use the shared table components and RowActions; the services list is explicitly marked, and the role-matrix navigation explicitly opts into record opening. Native tables with existing View buttons or identifying record links are also enhanced. Existing mutation confirmations and permission gates remain authoritative.

Developer contract: use `opensRecord: true` on a non-mutating RowAction whose label does not follow the read/open grammar. Standalone read controls can use `data-row-open="true"`. Do not apply either marker to writes. Existing table-row click handlers are marked `data-row-handled` by both shared renderers. `data-row-click-ignore` excludes custom interactive controls from row activation.

Validation: 631 unit tests, 17 group-workspace/row-navigation browser scenarios and 43 existing list/intake/Manage-confirmation regressions passed. Checks include keyboard opening, independent checkboxes/Manage actions, native-table controls, disabled views and text selection. TypeScript, scoped lint without autofix and isolated production build passed.
